1강. 콘솔, 터미널, 셸

설명 강의 ⏱ 약 30분

학습 목표

  • 콘솔, 터미널, 셸이 각각 무엇을 맡는지 구분해 말할 수 있습니다.
  • 콘솔이라는 낱말의 뜻이 과거의 물리 장치에서 현재의 논리적 입출력 환경으로 어떻게 달라졌는지 설명할 수 있습니다.

세 낱말은 왜 헷갈리는가

→ 세 낱말이 한 줄로 이어진 관계라는 것을 먼저 보고, 헷갈리는 이유를 알아봅니다.

명령이 지나가는 길

컴퓨터에 명령을 입력해 본 분이라면 "콘솔에 입력하세요", "터미널을 여세요", "셸에서 실행하세요"라는 안내를 모두 들어 보셨을 것입니다. 세 안내는 같은 검은 창을 가리키는 것처럼 들리는데, 실제로는 서로 다른 것을 가리킵니다.

여러분이 키보드로 명령을 입력하면 그 명령은 다음 순서로 지나갑니다.

💡 참고 사용자 → 터미널(입출력 창) → 셸(명령 해석기) → 커널(실행) → 하드웨어

  • 터미널은 셸을 사용자에게 보여 주는 화면 창입니다.
  • 셸은 그 창 뒤에서 입력한 명령을 해석해 실제로 실행하는 프로그램입니다.
  • 커널은 운영체제의 중심이어서, 셸이 넘긴 명령을 하드웨어에서 실행합니다.

여러분이 직접 만나는 것은 맨 앞의 터미널과 그 뒤의 셸입니다. 콘솔은 이 흐름에서 한 칸의 이름이라기보다, 역사 때문에 터미널과 뜻이 겹친 낱말입니다.

[이미지: 1강-1-1-0 — 장면 그림. 키보드 앞의 사용자가 명령을 입력하면 터미널 창, 셸, 커널, 하드웨어 순서로 명령이 전해지는 장면] ▲ 사용자가 입력한 명령이 터미널, 셸, 커널을 거쳐 하드웨어에 닿는 흐름

구분의 기준은 이름이 아니라 역할입니다

세 낱말은 실제로 구분 없이 섞어 쓰는 일이 많습니다. 그래서 이름의 사전적 정의를 외우기보다, 각각이 맡은 역할로 구분하는 것이 정확합니다.

  • 콘솔: 시스템과 직접 연결된 기본 입출력 환경
  • 터미널: 사용자가 컴퓨터에 접속하게 해 주는 창
  • 셸: 입력한 명령을 해석하는 프로그램

세 낱말은 이름이 아니라 ==역할==로 구분합니다.

콘솔은 장치에서 환경으로 바뀌었다

→ 콘솔이 물리 장치였던 과거와 입출력 환경을 뜻하는 현재를 비교합니다.

과거의 콘솔은 기계였습니다

콘솔은 텍스트로 입력하는 장치와 출력하는 장치를 함께 가진 하드웨어, 곧 기계를 가리켰습니다. 키보드와 모니터가 한 몸으로 붙은 단말기를 떠올리면 됩니다. 이 시절에 "콘솔에 입력해"라는 말은 콘솔이라는 하드웨어를 사용해서 명령을 입력하라는 뜻이었습니다.

서버실에 가서 컴퓨터에 직접 꽂혀 있는 모니터와 키보드 앞에 앉는 모습이 그 대표입니다.

현재의 콘솔은 논리적 환경입니다

오늘날 "콘솔에 입력해"는 콘솔이라는 소프트웨어를 사용해서 명령을 입력하라는 뜻으로 쓰입니다. 이때 콘솔은 시스템과 직접 연결된 논리적인 텍스트 기반 입출력 환경입니다. 리눅스의 TTY(가상 콘솔)가 그 예입니다.

장치를 켤 때 그래픽 화면 없이 검은 바탕에 흰 글자가 빠르게 올라가는 부팅 화면을 본 적이 있을 것입니다. 이것이 시스템 콘솔입니다. 서버의 부팅 기록이 찍히거나 오류 메시지가 출력되는 영역도 같은 성격으로, 시스템의 상태를 가장 직접 보여 주고 관리하는 주 화면입니다.

[이미지: 1강-2-2-0 — 장면 그림. 한쪽에는 키보드와 모니터가 붙은 옛 단말기 앞에 앉은 사람, 다른 쪽에는 노트북 화면의 터미널 창을 보는 사람을 나란히 놓은 장면] ▲ 물리 장치였던 과거의 콘솔과 소프트웨어 창으로 옮겨 온 현재의 모습

뜻이 겹친 것이 혼란의 시작입니다

과거의 콘솔이 하던 역할을 지금은 소프트웨어 터미널이 합니다. 그래서 콘솔이라는 낱말에는 과거의 하드웨어라는 뜻과 현재의 논리적 터미널이라는 뜻이 함께 남았고, 터미널이라는 용어가 콘솔의 개념과 겹치게 되었습니다. 세 낱말이 헷갈리는 이유가 여기에 있습니다.

콘솔은 물리적인 입출력 장치에서 논리적인 입출력 환경으로 뜻이 바뀐 낱말입니다.

터미널은 셸을 담는 창이다

→ 터미널이 무엇이고, 같은 컴퓨터에 여러 개를 띄워도 되는 이유를 알아봅니다.

소프트웨어가 된 콘솔

터미널은 과거에 물리적인 콘솔 기계가 하던 역할을 소프트웨어로 구현한 것입니다. 기술적으로 가장 정확한 이름은 터미널 에뮬레이터(Terminal Emulator)이고, 에뮬레이터라는 이름대로 옛 콘솔을 흉내 냅니다. 윈도우나 맥에서 우리가 띄우는 창이 바로 이것입니다.

실제 터미널의 예는 다음과 같습니다.

  • 리눅스: GNOME Terminal, KDE Konsole, xterm
  • 윈도우: Windows Terminal
  • 맥: iTerm2
  • 원격 접속: PuTTY

은행 창구와 같은 역할

터미널은 은행의 창구와 같습니다. 고객이 은행 업무를 맡기러 오는 접점이 창구이고, 창구를 여러 개 열어도 은행 시스템이 여러 개가 되지는 않습니다. 터미널도 마찬가지로 동시에 여러 개를 실행할 수 있지만, 컴퓨터는 하나입니다.

터미널은 사용자가 컴퓨터에 접속하는 접점이므로, 터미널을 바꾼다는 것은 창구의 겉모습을 바꾸는 것에 가깝습니다. 예를 들어 아이콘이 예쁜 iTerm2로 바꿨다면 디자인이 바뀐 것입니다. 명령을 해석하는 방식은 그대로입니다.

터미널은 셸을 사용자에게 보여 주는 ==창==이고, 바꾸면 모양이 달라집니다.

셸은 명령을 해석하는 프로그램이다

→ 셸이 실제로 무엇을 하는지, 어떤 종류가 있는지 알아봅니다.

입력한 명령을 운영체제에 전달합니다

셸은 사용자로부터 명령을 받아 해석하고, 그 명령을 운영체제의 커널에 전달해 처리하게 하는 프로그램입니다. 터미널이 보여 주는 창 뒤에서 실제로 일하는 쪽이 셸입니다.

우분투에서는 기본으로 bash를 쓰고, 다른 셸로 바꿔 쓸 수도 있습니다. 유닉스와 유닉스 계열 시스템에서 널리 쓰는 셸에는 sh, bash, ksh, zsh 등이 있습니다.

셸 종류 특징
bash Bourne Again Shell의 줄임말이고, 우분투의 기본 셸입니다
zsh bash보다 확장성이 강하고 테마가 풍부합니다(oh-my-zsh 등)
sh POSIX와 호환되는 기본 셸입니다
fish 자동 완성과 직관적인 사용법을 제공합니다

셸을 바꾸면 명령의 규칙이 달라집니다

bash에서 zsh로 바꿨다면 명령어의 문법이나 자동 완성 기능이 바뀐 것입니다. 창의 모양이 아니라 명령을 해석하는 방식이 바뀐 것이므로, 터미널을 바꿀 때와는 결과가 다릅니다.

셸은 입력한 명령을 ==해석==해서 운영체제에 전달하는 프로그램입니다.

실제 환경에서 구분해 보기

→ 터미널은 화면, 셸은 처리라는 기준으로 윈도우와 리눅스의 실제 환경을 가려 봅니다.

터미널은 UI, 셸은 로직

터미널은 사용자 인터페이스(UI)에 가깝고, 셸은 프로그램 로직에 가깝습니다. 정확히 같다고 말할 수는 없지만, 둘을 구분하는 가장 쉬운 기준입니다. 이 기준 하나로 "무엇을 바꿨을 때 무엇이 달라지는가"를 판단할 수 있습니다.

바꾼 것 달라지는 것
터미널 창의 디자인과 화면 구성
셸 명령어의 문법과 자동 완성 같은 기능

윈도우에서의 구분

  • cmd.exe(명령 프롬프트)와 PowerShell은 셸입니다.
  • 이 셸을 보여 주는 검은 창은 콘솔 호스트(conhost.exe) 또는 최신 Windows Terminal입니다.

윈도우에서는 PowerShell을 쓰면서 창은 Windows Terminal로 띄울 수 있습니다. 창과 프로그램이 서로 다른 것이기 때문에 가능한 조합입니다.

리눅스에서의 구분

  • 화면에 보이는 창은 터미널(GNOME Terminal 등)입니다.
  • 그 안에서 명령을 해석하는 로직은 셸(bash 등)입니다.

3강에서 설치된 라이브러리의 위치를 확인하는 명령을 입력할 때, 여러분은 이 구분을 그대로 씁니다. 명령을 입력하는 창이 터미널이고, 그 명령을 해석해 실행하는 것이 셸입니다.

창은 터미널, 명령을 해석하는 프로그램은 셸이라고 ==역할==을 나눠 부르면 헷갈리지 않습니다.

📌 정리

  • 콘솔은 과거에는 물리적인 입출력 장치였고, 현재는 시스템과 직접 연결된 논리적 입출력 환경입니다.
  • 터미널은 콘솔의 역할을 소프트웨어로 옮긴 창입니다. 여러 개를 띄워도 컴퓨터는 하나입니다.
  • 셸은 입력한 명령을 해석해 커널에 전달하는 프로그램입니다.
  • 터미널은 UI, 셸은 로직에 가깝고, 명령은 사용자 → 터미널 → 셸 → 커널 → 하드웨어 순서로 지나갑니다.

❓ 질문 아이콘이 예쁜 터미널로 바꿨더니 명령어의 문법도 달라졌다면, 무엇이 바뀐 것일까요? 터미널과 셸 가운데 어느 쪽이 원인인지 말해 보세요.
